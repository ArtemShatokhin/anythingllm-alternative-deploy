# Deploy an open-source AnythingLLM alternative with Kortix

Kortix is open source. This repository is a deploy template for a self-hosted alternative to AnythingLLM: you stand up a Kortix project and run a document-Q&A agent that answers over your own files. The project is code in a git repo you own, and the platform is the open-source AI Operating System.

## What "deploy an AnythingLLM alternative" means

AnythingLLM is an open-source, local-first document chat application from Mintplex Labs. It runs as a desktop app on macOS, Windows, and Linux, or as a self-hosted multi-user server, and it keeps a workspace of documents backed by a vector database ([docs.anythingllm.com](https://docs.anythingllm.com); [the AnythingLLM source repo](https://github.com/Mintplex-Labs/anything-llm)). It is built for private chat over documents you feed it.

Kortix is the open-source AI Operating System: your agents, skills, company memory, and connectors live in one git repo you own, and each session runs on its own cloud computer ([kortix.com](https://kortix.com)). Deploying an AnythingLLM alternative here means moving a document workspace into a project repo. The agent that answers your document questions becomes a markdown file, the rules for what it may touch become a block in `kortix.yaml`, and every change the agent proposes reaches the default branch through a change request a person reviews first.

Both products are open source. Kortix moves the workspace, the agents, and the schedules out of an app and into files you can read, diff, and version.

## The stack it deploys

A Kortix project is a git repo plus a `kortix.yaml` manifest at the root. The manifest declares the agents, the connectors they may reach, the secrets they may use, and the triggers that start work. The behavioral half of each agent lives in `agents/<name>.md`, and shared know-how lives in `skills/<name>/SKILL.md` ([manifest reference](https://kortix.com/docs/project/manifest); [agents](https://kortix.com/docs/project/agents)).

Self-hosting runs one Docker Compose stack: the frontend, the API, the LLM gateway, and the Supabase distribution. Agent sessions run on a separate sandbox provider rather than on that stack ([self-hosting](https://kortix.com/docs/host)). The official Compose file is generated by `kortix self-host init` and pins each image by digest, so `docs/02` shows both the generated path and a readable map of the stack.

## Quick start

Every command below is from the Kortix CLI and self-hosting docs, and none is invented ([CLI reference](https://kortix.com/docs/cli); [self-hosting](https://kortix.com/docs/host)).

```bash
# 1. Install the kortix CLI (macOS and Linux)
curl -fsSL https://kortix.com/install | bash

# 2. Scaffold a project: a kortix.yaml plus starter agents and runtime config
kortix init my-doc-qa
cd my-doc-qa

# 3. Replace the starter files with the preset in docs/03, then push it live
kortix ship

# 4. Start a session: a sandbox boots on its own branch
kortix sessions new --prompt "Index the documents in docs/ and answer: what does our refund policy cover?"
```

To run the platform on your own box instead of Kortix Cloud, install the CLI and use the self-host commands in [docs/02-docker-compose.md](docs/02-docker-compose.md). Self-host is free.

## How it compares to AnythingLLM

The table below states what each project documents about itself. The AnythingLLM facts come from its docs and its source repo; the Kortix facts come from the Kortix docs and [Kortix on GitHub](https://github.com/kortix-ai/suna).

| | Kortix | AnythingLLM |
| --- | --- | --- |
| Source | Open source | Open source |
| What it is | AI Operating System | Document chat app |
| Where the config lives | Files in a git repo you own | Settings inside the app |
| Where it runs | Cloud, your VPC, or on-prem | Your machine or a self-hosted server |
| What it returns | Finished files from cloud computers | Answers over your documents |

AnythingLLM suits private chat over a fixed set of documents on one machine. Kortix suits company work that needs agents to reach several tools, read shared context, and land reviewed changes in a repo.
